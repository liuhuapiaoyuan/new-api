## 部署结构

- Nginx 站点配置：`/www/server/panel/vhost/nginx/ai-api.qzsyzn.com.conf`
- 反代规则：`/www/server/panel/vhost/nginx/proxy/ai-api.qzsyzn.com/*.conf`  
  → 反代本机 `127.0.0.1:4847` → 容器内 `3000`
- Compose 项目名：`newapi`
- 业务镜像：`docker.cnb.cool/qzsyzn/docker/newapi:latest`
- 容器：
  - `newapi-new-api-1`（端口 `4847:3000`，挂载 `./data`、`./logs`）
  - `newapi-postgres-1`（`postgres:15`，数据目录 `./pg_data`）
  - `newapi-redis-1`（`redis:latest`，无持久化卷）
- 应用侧关键配置（来自 `docker-compose.yml`）：
  - `SQL_DSN=postgres://root:***@postgres:5432/new-api`
  - `REDIS_CONN_STRING=redis://redis`
  - `TZ=Asia/Shanghai`
  - `ERROR_LOG_ENABLED=true`
  - `BATCH_UPDATE_ENABLED=true`
  - `STREAMING_TIMEOUT=6000`
- 对外站点名（`/api/status`）：`双源AI网关`，`server_address=https://ai-api.qzsyzn.com`

目录占用（约）：

- `pg_data` ≈ 2.3G（当前在用）
- `logs` ≈ 2.9G
- 另有历史残留目录 `pg_data3`、`pg_data-副本`（非当前挂载）

## 常用操作

查看状态：

```bash
cd /www/wwwroot/ai-api.qzsyzn.com/newapi
docker compose ps
curl -s http://127.0.0.1:4847/api/status
```

发版 / 更新镜像：

```bash
cd /www/wwwroot/ai-api.qzsyzn.com/newapi
docker compose pull new-api
docker compose up -d --no-deps --force-recreate new-api
```

只改 `docker-compose.yml` 环境变量后重建业务容器：

```bash
cd /www/wwwroot/ai-api.qzsyzn.com/newapi
docker compose up -d --no-deps --force-recreate new-api
```

日志：

```bash
# 容器日志
docker logs -f --tail=200 newapi-new-api-1

# 应用文件日志
ls -lt /www/wwwroot/ai-api.qzsyzn.com/newapi/logs | head
```

Nginx 访问 / 错误日志：

- `/www/wwwlogs/ai-api.qzsyzn.com.log`
- `/www/wwwlogs/ai-api.qzsyzn.com.error.log`

## 注意

1. **无备份**：数据库在 `./pg_data`，目前没有自动备份；改库、迁库、清日志前先手动快照。
2. Compose 里 Postgres 账号口令仍是默认弱口令，生产环境应尽快更换（同时改 `SQL_DSN` / `POSTGRES_PASSWORD`）。
3. `logs` 已接近 3G，可按日期清理旧 `oneapi-*.log`，避免占满磁盘。
4. `pg_data3`、`pg_data-副本` 不是当前容器挂载，确认无用后再删，避免误删在用数据。
